# Open Space HDL Reference Systems

Complete systems built from the [Open Space HDL](https://openspacehdl.org) cores, with board targets. Every system is
defined by one file of the [Open Space Composer](https://openspacehdl.org/composer/): the cores it uses, their
generics, connections and clocks, and the exact versions of the cores. The Composer generates the VHDL top level of
the system from that file. This repository adds what turns the top level into a working design: a system testbench, a
board top level per target with its constraints and build script, and a hardware test procedure.

## Layout

| Path | Content |
| --- | --- |
| `systems/<system>/<system>.composer.json` | Definition of the system, edited only in the Composer |
| `systems/<system>/hdl/` | VHDL top level generated by the Composer from the system file, never edited by hand |
| `systems/<system>/sim/` | System testbench |
| `systems/<system>/targets/<board>/` | Board top level, block design script, constraints, build script, hardware test |
| `systems/<system>/docs/` | What the system does, address map, initialisation sequence |
| `systems/<system>/sw/` | Host software of the system, for example its hardware test |
| `cores/` | Submodules: Open Logic FT and every core, at the commits the system files pin |
| `sim/` | The far end of the system testbenches ([sim/README.md](sim/README.md)) |
| `sw/refsys/` | Python library of the host software: RMAP, Space Packets, OpenCrypto chunks, OpenCompact images and channel model, register maps, facts of a system file, transports, the shared parts of the hardware tests, their pytest plugin and step log, the system models and the stimuli of the system simulations |
| `tools/` | Checks of the repository (core versions, generated top levels), the Composer version of the generated top levels (`composer_ref.txt`), the Vivado reader of the Composer compile order and the constraint check of the implementation runs (`tools/vivado/`), the simulators (`xsim.py`, `ghdl.py`) and the runner of the system testbenches (`sysbench.py`), the offline package of a build (`make_offline_bundle.py`) |
| `lint/` | VSG configuration and lint script of the hand-written VHDL |
| `run.py` | VUnit run script: compiles the libraries of all systems and runs their testbenches |

The [conventions](docs/conventions.md) describe the rules of the repository in detail.

## Quick start

```shell
git clone https://github.com/open-space-hdl/reference-systems.git
cd reference-systems
git submodule update --init
git -C cores/open-logic-ft submodule update --init 3rdParty/en_cl_fix
python -m pip install -r requirements.txt
python tools/check_pins.py        # the submodules match the system files
python run.py --compile           # analyses Open Logic FT and the cores with GHDL
python -m pytest                  # host software and system tests against their software models
```

The submodules of the cores themselves (their own `open-logic` and `uvvm`) serve the tests of the cores and are not
needed here: a system compiles all cores against one Open Logic FT library, the one in `cores/open-logic-ft`.

## Adding a system

1. Build the system in the [Composer](https://openspacehdl.org/composer/) and save it as
   `systems/<system>/<system>.composer.json`; the system name of the file, the directory and the file name are the
   same.
2. Its section `sources` pins every core and Open Logic FT. All systems of the repository use the same versions,
   since they share `cores/`: either pin the versions that are already there, or move all systems to new versions in
   the same change (see [Core versions](docs/conventions.md#core-versions)).
3. Generate the top level into `systems/<system>/hdl/` with the command line tool of the Composer at the commit of
   `tools/composer_ref.txt`:

   ```shell
   git clone https://github.com/open-space-hdl/open-space-hdl.github.io.git .composer
   git -C .composer checkout $(cat tools/composer_ref.txt)
   python tools/check_hdl.py --composer .composer --write
   ```

4. Add the system to the table in [Status](#status), write its `README.md`, then its testbench and targets.
5. `python tools/check_pins.py`, `python tools/check_hdl.py --composer .composer` and `python run.py --compile` pass.
